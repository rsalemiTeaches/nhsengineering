In Project 02 you typed a bouncing square by hand, line by line.

This project is different. You will not write a single line of code.

Instead you will describe what you want in plain English. You hand that description to Ollama, a coding AI running on this computer, and it writes the program.

# A new way of building

The rule for this class changes now.

You do not have to read the code Ollama writes. You are not expected to understand it line by line.

You have two jobs instead.

The first is writing a clear description of what the program should do. That description is called a **prompt**.

The second is checking that the program does what you asked.

If it does not match, that is a signal to ask again. It is not a bug you are supposed to find by reading the code.

For this project the prompt is written for you. Starting next project you write your own.

# Exercise 1: Prompt Ollama for a Bouncing Circle

## Step 1: Make a folder for this project

```
cd $HOME
cd swdev
mkdir proj03
cd proj03
```

## Step 2: Open Ollama and give it the prompt

Open the **Ollama** app.

At the bottom of the window is the **Select Model** pulldown. Click it and choose `qwen2.5-coder:7b`. That is the model that writes code.

Do this every time you open the app.

![[CleanShot 2026-08-19 at 11.36.31.png]]

Type the following into the message box, exactly as written, and press Return:

```
Write a Python program using pygame. Open a 500 by 400 pixel window with a
light gray background. Draw a circle with a 60-pixel radius that starts in
the middle of the window and moves in a straight line at an angle. When the circle touches any edge of the window, make it bounce back in the other 
direction and change to a new random color. Run the animation at 60 frames per
second, and keep the window open until the user closes it.
```

Ollama writes back an explanation and a block of Python code.

![[CleanShot 2026-08-19 at 11.42.54 2.png]]

## Step 3: Copy the code

Wait for Ollama to finish. Sometimes this takes a while, and a half-written block can look finished.

Ollama may show more than one block. One is short and labeled **bash**, for installing packages. Skip it — Step 5 installs pygame for you.

Find the block labeled **python**. Click the **Copy** button in its upper right corner.

That copies the code only, without Ollama's explanation around it.

## Step 4: Put the code in a file

```
touch circle.py
cot circle.py
```

Paste the code into the CotEditor window. Save it with **Command-S**.

Leave the window open. You will be back.

## Step 5: Tell uv this program needs pygame

```
uv add --script circle.py pygame
```

## Step 6: Run it

```
uv run circle.py
```

## Step 7: If it crashes

Sometimes you get a wall of red text in Terminal instead of a window. The last line usually starts with a name like `AttributeError:` or `SyntaxError:`.

That is a **crash**. It means the program never ran at all.

This is normal. An AI that writes code does not always get every detail right the first time.

You do not need to work out what the error means. Hand it back to the AI:

1. Copy the error text from Terminal. The last several lines are enough.
2. Go back to Ollama, in the same chat.
3. Paste the error and add: "This crashed with the error above. Please fix it."
4. Copy the new **python** block Ollama sends back.
5. Click into the CotEditor window. Select everything with **Command-A**, paste over it with **Command-V**, and save with **Command-S**.
6. Run it again, the same way as Step 6.

If it crashes again, do the same thing with the new error.

## Step 8: Check it against the prompt

Once it runs, do not look at the code. Look at the window.

Check it against what the prompt asked for:

- Does a light gray window open, about 500 by 400 pixels?
- Does a circle appear and move smoothly?
- When it reaches an edge, does it bounce back the other way?
- Does its color change when it bounces?
- Does it keep running until you close the window?

If all five are true, Ollama built what you asked for.

## Step 9: If it runs but does not match

Maybe the circle does not change color. Maybe it stops at the edge instead of bouncing.

Go back to Ollama and send the same prompt again.

Asking again is a normal part of the process. It is not a sign you did something wrong.

