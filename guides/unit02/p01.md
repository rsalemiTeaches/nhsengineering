Later in this unit, you will describe programs in plain English and have an AI write the code for you. Before that, you need the tools every project this term depends on: a terminal, a project folder tracked with git, a way to run Python called uv, and a plain text editor. This project gets you started with all four, so you never have to think about them again.

# Exercise 1: Set Up Your Tools

## Step 1: Open the Terminal

A terminal is a way to control your computer by typing commands instead of clicking icons. Everything in this unit happens there.

Press ⌘-Space, type "Terminal", and press Return.

## Step 2: Put your three apps in the Dock

You will open the same three apps every class for the rest of the term. Pin them now so you are not hunting for them each time.

While Terminal is open, its icon is sitting in the Dock at the bottom of the screen. **Right-click that icon, go to Options, and choose Keep in Dock.**

Now do the same for the two apps you will use with it. Open each one from the Applications folder — or with ⌘-Space, the way you opened Terminal — and Keep in Dock:

- **Ollama**, the AI that will write your code
- **CotEditor**, the editor you will type in

You should end up with Terminal, Ollama and CotEditor all sitting in the Dock. Do this once and it stays.

## Step 3: Make a home for your work

Type this and press Return:

```
mkdir swdev
```

`mkdir` means "make directory" — it creates a folder. You just created a folder named `swdev`, short for "software development." Every project you build this term will live inside it.

Now move into that folder:

```
cd swdev
```

`cd` means "change directory." Your terminal now treats `swdev` as the folder you are working in, so any command you type next happens there.

## Step 4: Turn your work folder into a git repository

Git is a tool that saves snapshots of your code as you go, called **commits**. Once something is committed, you can always get back to that exact version, even if you break everything after it. 

```
git init
```

This turns `swdev` into a git repository. Nothing is saved yet — `git init` just tells git to start watching this folder for changes.

## Step 5: Meet uv

uv is a tool that runs Python and manages **packages** — code someone else already wrote that your program can use instead of you writing it from scratch. Later this unit, you'll use a package named `pygame` to build your game. Instead of installing Python and packages by hand, you tell uv what you need and it handles the rest, one project at a time.

uv is already on this Mac. Check that you can reach it:

```
uv --version
```

If you see a version number, you are set. If you see `command not found`, stop and tell your teacher — nothing else in this unit will work until that does.

## Step 6: Make a folder for this project

Every project gets its own folder inside `swdev`.

```
mkdir proj01
cd proj01
```

## Step 7: Write your first program

A code editor is different from Word or Pages — it saves plain text with no hidden formatting, which is exactly what a program file needs to be. The one on this Mac is called **CotEditor**. You will write this first program by hand, so you know what a real Python file looks like before you start asking an AI to write them for you.

First make an empty file for the program to go in:

```
touch hello.py
```

`touch` creates a file with nothing in it. Now open that file in the editor:

```
cot hello.py
```

`cot` is CotEditor's command. It opens the file you name, in a real window, alongside your Terminal — you will use both at once for the rest of this unit, so leave them both open.

Type exactly this:

```
print("Hello, world!")
```

Save it with **Command-S**, the same as any other Mac app. You do not need to close the window. Leave CotEditor open and click back to Terminal.

## Step 8: Run it

```
uv run hello.py
```

You should see:

```
Hello, world!
```

`hello.py` doesn't need any packages, so uv just finds a Python interpreter and runs the file directly. Starting next project, you will see uv install a package before it runs your code — that is uv doing the same job on a program that needs more than plain Python.

## Step 9: Save your work with git

Move back up to your `swdev` folder:

```
cd ..
```

Stage and commit your work:

```
git add .
git commit -m "My first program"
```

`git add .` tells git which changed files to include in the next snapshot — in this case, everything. `git commit` takes that snapshot permanently and records the message you gave it, so later you can look back and see what you built and when. Every project this term ends with a commit like this one.
