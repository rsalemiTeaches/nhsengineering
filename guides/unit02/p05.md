Your player moves. So does everybody else's.

A paddle that slides and a frog that hops are not what makes one game Pong and another Frogger. One mechanic does that, and this project adds yours.

It is also the first time you will ask Ollama to change a program that already exists, instead of writing one from nothing.

# Changing a program you already have

Every prompt you have written so far asked for a whole program.

This one is different. You hand Ollama the code you already have, then ask for one thing to be added to it.

Three rules make this work.

**Start a new chat.** Do not keep adding to the Project 04 conversation.

You saw in Project 04 why a long chat gets slow, and that one is already long. Nothing in it is worth carrying over. Your `game.py` and your `PRD.md` are the record of your game.

**Attach both files.** `game.py` is what your program does right now. `PRD.md` is what it is supposed to do.

Send only the code and the AI cannot tell a feature from a bug. It sees a frog that hops 40 pixels and has no idea whether that is your design or the thing you want fixed.

Send only the PRD and it has nothing to add to.

Every new chat for the rest of this unit gets both.

**Ask for one thing.** Attaching your whole PRD is not the same as asking for your whole game.

The PRD is there so the AI knows what it must not break. What you *ask for* is one line of it, the new part.

Not the mechanic and a score. Not the mechanic and better colors. One thing. Then run it. Then check it.

# Exercise 1: Add Your Game's Core Mechanic

## Step 1: Find your mechanic

Read only your own game.

### If your game is Pong

Add a ball.

It moves in a straight line and bounces off the top, bottom and right walls. That is the same bounce you built by hand in Project 02.

It also bounces off your paddle.

If it gets past the paddle and off the left edge, it starts again in the middle of the window.

### If your game is Breakout

Add a ball and a row of bricks.

The ball moves in a straight line. It bounces off the top, left and right walls, and off your paddle.

Put a row of bricks across the top of the window. When the ball hits a brick, that brick disappears and the ball bounces off it.

If the ball goes off the bottom of the window, it starts again in the middle.

### If your game is Snake

Add food.

A small square appears in a random spot in the window.

When the snake's head touches it, the food disappears and a new one appears somewhere else at random. The snake gets one square longer.

The body follows the head.

### If your game is Space Invaders

Add shooting, and something to shoot.

Pressing the spacebar fires a bullet straight up from your ship.

Put a row of invaders across the top of the window. When a bullet hits an invader, both the bullet and that invader disappear.

### If your game is Frogger

Add cars.

Put one lane of cars across the middle of the window. They all move the same direction at a steady speed.

When one goes off the side, another comes in from the other side.

If the frog touches a car, the frog goes back to its starting spot at the bottom.

## Step 2: Update your PRD first

```
cd $HOME
cd swdev
cd game
cot PRD.md
```

Add a new section for what you just read. Write it in your own words, with real numbers in it — how fast, how big, how many.

Say what should happen, not how to make it happen.

Save with **Command-S**.

The PRD gets updated before the code, every time. Change the game and not the PRD, and the PRD stops being the record of your game. Then you have nothing to check against.

## Step 3: Start a new Ollama chat

In the Ollama app, start a **new chat**.

Check the **Select Model** pulldown at the bottom of the window still says `qwen2.5-coder:7b`. Set it if it does not.

## Step 4: Give it both files and the one new thing

Attach `PRD.md` and `game.py`. Use the **+** button, or drag them in — the same two ways you learned last project.

If you want a Finder window to drag from, `open .` in Terminal gives you one.

Then type this into the message box:

```
The PRD describes what this program should do. The Python file is what
I have working so far. Add one thing to it:
```

Write the new requirement next, in the same words you just put in your PRD.

Finish with this:

```
Do not change anything else about the program.
```

That last line matters. Without it, an AI will often rewrite parts you never asked it to touch.

Press Return.

## Step 5: Replace your program

Copy the **python** block from Ollama's answer.

Click into the `game.py` tab in CotEditor. Select everything with **Command-A**, paste over it with **Command-V**, and save with **Command-S**.

Then run it:

```
uv run game.py
```

If it says pygame is not found, run this and try again:

```
uv add --script game.py pygame
```

Replacing the whole file wiped the note at the top that told uv what this program needs. That is all that error means.

## Step 6: If it crashes

Same loop as before.

Copy the error out of Terminal. Paste it into the same Ollama chat and add "This crashed with the error above. Please fix it."

Then put the corrected code back in `game.py`.

## Step 7: Check it against your PRD — all of it

This is the important part of this project, and it is new.

Check **two** things, not one:

1. Does the new mechanic work the way your PRD says?
2. Does everything from Project 04 still work?

Go back and move your player with the arrow keys. Check the edges again. Check that it still starts in the right place.

An AI rewriting your program can quietly break something that used to work. A paddle that used to stop at the edge now slides off. A frog that used to hop one step now glides.

Nobody tells you when this happens.

Attaching your PRD makes it less likely, because the AI can see what it is supposed to leave alone. It does not make it impossible.

Checking is still your job, and your PRD is the checklist you check with. That is the second reason it is worth keeping complete.

## Step 8: If it runs but does not match

Tell Ollama in the same chat exactly what is wrong, in one or two sentences. Describe what you see and what you expected.

For example: "The ball goes straight through the paddle instead of bouncing off it."

If it broke something from Project 04, say that instead: "The paddle used to stop at the top of the window and now it slides off the screen. Please fix that and leave everything else alone."

If the chat has gotten slow, stop and start a fresh one with your current code. Do it the same way as Steps 3 and 4.
