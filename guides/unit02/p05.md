Now you can move your sprite using the controls.  Next we have to add other sprites to make this into a game.  Other sprites can be a ball (in Pong) or a car (in Frogger) or anything else that moves in the game. 

We're going to add an additional sprite in this project and then more of them in the next project. 

In this project, you will ask Ollama to change a program that already exists, instead of writing one from nothing.

# Changing a program you already have

Now that we have the program started we need to add functionality to it.  We do this by creating a new chat in Ollama and giving it three things:

1. An updated PRD.md with the new features that we want.
2. The existing code.
3. A prompt to highlight what needs to be changed.

Now Ollama can add the feature. In this project, we are going to add the next element to the game.

# Exercise 1: Add the Next Element

## Step 1: Write the new PRD section

Right now your sprite moves around an empty window. Nothing else is there, so there is nothing to play against.

This project adds one thing to the window: **a second game element that your sprite interacts with.** In Pong that is the ball. In Snake it is the food. Whatever it is in your game, it is the thing that turns a moving shape into something you can play.

You describe it before Ollama builds it. That description is a new section in your PRD.

Open your PRD:

```
cd $HOME
cd swdev
cd game
cot PRD.md
```

Your PRD has four sections from Project 04: **The window**, **Your sprite**, **The controls**, and **Your sprite at the edges**.

Leave all four alone. Your new element gets a fifth section, at the bottom of the file.

That section has to answer five questions. One line each.

```
## <sprite name> (ball, car, food, etc)
1. <What shape is it, how big in pixels, and what color?>
2. <Where does it start?>
3. <How does it move, and how fast, in pixels per frame?>
4. <What does it touch, and what happens when it does?>
5. <What happens when it leaves the window?>
```

Make sure you have answered all five questions in your PRD.md file for this sprite.

If you skip a question, the AI will make something up. It's unlikely to guess correctly.

Put real numbers in. "The ball moves 4 pixels per frame" is something you can check on screen. "The ball moves fast" is not.

Say what should happen, not how to make it happen. That is the AI's job.

Now find your game below. It tells you what your new sprite does — questions 4 and 5, mostly. **The shape, the size, the color and the speed are yours to decide**, and your game's paragraphs will not tell you them.

Read only your own game.

### If your game is Pong

Your heading is `## The ball`.

The ball moves in a straight line and bounces off the top, bottom and right walls. That is the same bounce you built by hand in Project 02.

It also bounces off your paddle.

If it gets past the paddle and off the left edge, it starts again in the middle of the window.

### If your game is Breakout

Your heading is `## The ball and the bricks`.

The ball moves in a straight line. It bounces off the top, left and right walls, and off your paddle.

A row of bricks sits across the top of the window. When the ball hits a brick, that brick disappears and the ball bounces off it.

If the ball goes off the bottom of the window, it starts again in the middle.

### If your game is Snake

Your heading is `## The food`.

One piece of food sits in a random spot in the window.

When the snake's head touches it, the food disappears and a new piece appears somewhere else at random. The snake gets one square longer.

The body follows the head.

### If your game is Space Invaders

Your heading is `## The bullets and the invaders`.

Pressing the spacebar fires a bullet straight up from your ship.

A row of invaders sits across the top of the window. When a bullet hits an invader, both the bullet and that invader disappear.

### If your game is Frogger

Your heading is `## The cars`.

One lane of cars crosses the middle of the window. They all move the same direction at a steady speed.

When one goes off the side, another comes in from the other side.

If the frog touches a car, the frog goes back to its starting spot at the bottom.

### Write it

Type your heading into `PRD.md`, then your five answers under it.

Save with **Command-S**.

Update the PRD before the code, every project. Change the game and not the PRD, and you have nothing left to check your game against.

## Step 2: Start a new Ollama chat

In the Ollama app, start a **new chat**.

Check the **Select Model** pulldown at the bottom of the window still says `qwen2.5-coder:7b`. Set it if it does not.

## Step 3: Give it both files and the one new thing

Attach `PRD.md` and `game.py`. Use the **+** button, or drag them in — the same two ways you learned last project.

If you want a Finder window to drag from, `open .` in Terminal gives you one.

Then type this into the message box:

```
The PRD describes what this program should do. The Python file is what
I have working so far. Add one thing to it:
```

Write the new requirement next, in the same words you just put in your PRD.

Finish with this:

```
Do not change anything else about the program.
```

That last line matters. Without it, an AI will often rewrite parts you never asked it to touch.

Press Return.

## Step 4: Replace your program

Copy the **python** block from Ollama's answer.

Click into the `game.py` tab in CotEditor. Select everything with **Command-A**, paste over it with **Command-V**, and save with **Command-S**.

Then run it:

```
uv add --script game.py pygame; uv run game.py
```

## Step 5: If it crashes

Same loop as before.

Copy the error out of Terminal. Paste it into the same Ollama chat and add "This crashed with the error above. Please fix it."

Then put the corrected code back in `game.py`.

## Step 6: Check it against your PRD — all of it

This is the important part of this project, and it is new.

Check **two** things, not one:

1. Does the new element work the way your PRD says?
2. Does everything from Project 04 still work?

Go back and move your sprite with the arrow keys. Check the edges again. Check that it still starts in the right place.

An AI rewriting your program can break something that used to work. A paddle that used to stop at the edge now slides off. A frog that used to hop one step now glides.

Nobody tells you when this happens. Checking is your job, and your PRD is the checklist.

## Step 7: If it runs but does not match

Tell Ollama in the same chat exactly what is wrong, in one or two sentences. Describe what you see and what you expected.

For example: "The ball goes straight through the paddle instead of bouncing off it."

If it broke something from Project 04, say that instead: "The paddle used to stop at the top of the window and now it slides off the screen. Please fix that and leave everything else alone."

If the chat has gotten slow, stop and start a fresh one with your current code. Do it the same way as Steps 2 and 3.

## Step 8: Save your work

```
cd ..
git add .
git commit -m "Project 05: next element"
git tag p05
```
