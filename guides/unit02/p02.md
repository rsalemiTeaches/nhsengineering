# How video game animation works

Ollama will write most of your code this term. You still need to know the basics of how it works.

Animation is many pictures shown quickly, each one a little different from the last. These pictures animate a horse running:

![[Pasted image 20260819072308.png]]

Film and video need at least 24 pictures per second to look smooth. Each picture is called a **frame**.

An artist draws every frame in advance. A video game cannot do that. It draws each frame as the game happens.

That creates a problem. If the player watched the game draw a frame, it would look strange.

So a game keeps two frames. It shows one and draws in the other. When the drawing is done, it flips them instantly.

In this project, pygame draws a square that bounces off the walls. It shows 60 frames per second. It keeps going until you click the X in the window.

## Step 2: Write the program

Make the file and open it:

```
touch square.py
cot square.py
```

Type exactly this:

```
# COMMENTS
# You do not have to type things that come after a pound-sign (#)
# These are comments.  The program does not run them.

# Tell Python that we want to use the things in the pygame package.
import pygame

# set up the game.  Notice how we call the `init()` function from pygame
# by using dot (.)
pygame.init()

# Now we set up the display to be 400x300 pixels
screen = pygame.display.set_mode((400, 300))

# The clock will let us run at 60 frames per second
clock = pygame.time.Clock()


size = 100  # Set up the size of the square
x, y = 150, 100 # Set the position of the square's top left corner

# This is how fast the square moves.
# The square moves 3 pixels to the right per frame
# The square moves 2 pixels down per frame
# We flip the sign on these to change direction.
dx, dy = 3, 2  

running = True

# This loop runs until we click the window's close button
while running:

    # Check to see if the user has clicked the close button
    # this is the event pygame.QUIT
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    # Move the square
    x += dx
    y += dy

    # If the square hits the left or right side of the window, change the x direction
    if x <= 0 or x + size >= 400:
        dx = -dx

    # If the square hits the top or bottom of the window, change the y direction
    if y <= 0 or y + size >= 300:
        dy = -dy

    # We are now drawing a new frame.

    # First, clear everything from the old frame.
    screen.fill((0, 0, 0))

    # Now, draw a white (255,255,255) square at x and y with the size.
    pygame.draw.rect(screen, (255, 255, 255), (x, y, size, size))

    # The new frame is drawn.  Flip it!
    pygame.display.flip()

    # Wait so that we will draw 60 frames per second.
    clock.tick(60)

# The user clicked the close button.  Time to go!
pygame.quit()
```

Save it with **Command-S**, then click back to Terminal.

Leave the editor open. If the program does not work, you will come back to fix a typo.

## Step 3: Understand what you just typed

`import pygame` brings in the pygame package so your program can use it.

`pygame.init()` wakes up everything pygame needs.

`pygame.display.set_mode((400, 300))` opens a window 400 pixels wide and 300 tall. It hands back a **surface**, which is pygame's name for something you can draw on.

`clock = pygame.time.Clock()` makes a clock that paces the loop.

Without the clock, the loop runs as fast as the Mac can go. That can be thousands of times a second, and the square would shoot across the screen too fast to see.

`clock.tick(60)` sits at the bottom of the loop. It waits just long enough each pass to hold the loop to about 60 times a second. That is true on any Mac.

`size = 100` is how big the square is, in pixels.

`x, y = 150, 100` is where its top-left corner starts.

`dx, dy = 3, 2` is how far `x` and `y` change on each pass through the loop. The `d` is short for "the difference this pass."

`while running:` is the heart of every pygame program. It runs over and over, as fast as `clock.tick(60)` allows, for as long as `running` stays `True`.

`for event in pygame.event.get():` checks everything that happened since the last pass. That includes a key press, a mouse click, or the close button.

Your program never sends `pygame.QUIT` itself. macOS sends it the moment you click the close button.

`if event.type == pygame.QUIT:` catches that one event and sets `running` to `False`. That ends the loop.

So clicking the close button is what ends the program. Without that line, the click would do nothing and macOS would think your program had frozen.

`x += dx` and `y += dy` move the square a little on every pass. This happens 60 times a second, so it looks like smooth motion instead of jumping.

The two `if` lines are the bounce.

`x + size` is the square's right edge. When that edge reaches `400`, or when `x` reaches `0`, then `dx = -dx` flips the sign of `dx`. The square starts moving the other way.

The `y` check does the same thing against the top and bottom.

`screen.fill((0, 0, 0))` paints the whole window black before anything new is drawn. Skip it and the square smears a trail behind it.

`pygame.draw.rect(screen, (255, 255, 255), (x, y, size, size))` draws the square. It draws on `screen`, in the color `(255, 255, 255)`, at the square's current position and size.

A pygame color is three numbers: how much red, green and blue light to mix. `(0, 0, 0)` is black. `(255, 255, 255)` is white.

`pygame.display.flip()` shows what you just drew. This is the frame flip from the start of this guide.

`pygame.quit()` shuts pygame down cleanly once the loop ends.

## Step 4: Tell uv this program needs pygame

`square.py` needs a package that plain Python does not include.

```
uv add --script square.py pygame
```

This writes a short note at the top of `square.py` naming the package this file needs.

From now on, `uv run square.py` installs pygame the first time and reuses it after that. You never install it by hand.

## Step 5: Run it

```
uv run square.py
```

A black window should open with a white square bouncing inside it.

Click the close button, the red circle in the top-left corner, to end the program.
