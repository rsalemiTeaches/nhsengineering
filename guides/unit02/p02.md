# The basics of video game animation
We will be creating a video game in this project, and so we'll need to understand a little about video game animation.  Ollama will write most of our code, but we should know the basics of how the code works.

As you might know, animation works by presenting many pictures quickly, with small changes in each picture. These pictures animate a horse running:

![[Pasted image 20260819072308.png]]

With film or video, we present many frames per second (at least 24 frames per second for smooth animation.)  When artists create animation, they draw all the frames in advance.  In a video game, we draw the frames based on what is happening in the game.

The challenge with a video game is that we cannot let the user see us drawing the frame.  That would look weird.  To avoid that, we maintain two frames.  We present one frame and draw in the other frame.  Then we instantly flip the frames when we are done drawing.

In this assignment, you'll see the `pygame` package draw a moving square that bounces off the walls.  It will loop until you click the X in the window, and it will draw the square and then flip it based on whether the square has bounced off a wall.

We will present 60 frames per second to be smooth.

## Step 2: Write the program

Open the editor:

```
pico square.py
```

Type exactly this:

```
# COMMENTS
# You do not have to type things that come after a pound-sign (#)
# These are comments.  The program does not run them.

# Tell Python that we want to use the things in the pygame package.
import pygame

# set up the game.  Notice how we call the `init()` function from pygame
# by using dot (.)
pygame.init()

# Now we set up the display to be 400x300 pixels
screen = pygame.display.set_mode((400, 300))

# The clock will let us run at 60 frames per second
clock = pygame.time.Clock()


size = 100  # Set up the size of the square
x, y = 150, 100 # Set the position of the square's top left corner

# This is how fast the square moves.
# The square moves 3 pixels to the right per frame
# The square moves 2 pixels down per frame
# We flip the sign on these to change direction.
dx, dy = 3, 2  

running = True

# This loop runs until we click the X in the window
while running:
	
	# Check to see if the user has clicked the X
	# this is the event pygame.QUIT
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

	# Move the square
    x += dx
    y += dy

	# If the square hits the left or right side of the box change the x direction
    if x <= 0 or x + size >= 400:
        dx = -dx
        
    # If the square hits the top or bottom of the box change the y direction
    if y <= 0 or y + size >= 300:
        dy = -dy

	# We are now drawing a new frame.  
	
	# First, clear everything from the old frame.  
    screen.fill((0, 0, 0))
    
    # Now, draw a white (255,255,255) square at x and y with the size.
    pygame.draw.rect(screen, (255, 255, 255), (x, y, size, size))
    
    # The new frame is drawn.  Flip it!
    pygame.display.flip()
    
    Wait so that we will draw 60 frames per second.
    clock.tick(60)

# The user pressed X.  Time to go!
pygame.quit()
```

Save and exit: press **Control-O**, then **Return** to confirm the filename, then **Control-X** to leave the editor.

## Step 3: Understand what you just typed

`import pygame` brings in the pygame package so your program can use it.

`pygame.init()` wakes up everything pygame needs before you use it.

`pygame.display.set_mode((400, 300))` opens a window 400 pixels wide and 300 pixels tall, and hands you back a **surface** — pygame's name for something you can draw on.

`clock = pygame.time.Clock()` makes a clock pygame uses to pace the loop. Without it, the loop runs as fast as the computer possibly can — thousands of times a second on some Macs — and the square would shoot across the screen too fast to see. `clock.tick(60)`, at the bottom of the loop, waits just long enough each pass to keep the loop to about 60 times a second, no matter which Mac it runs on.

`size = 100` is how big the square is, in pixels. `x, y = 150, 100` is where its top-left corner starts. `dx, dy = 3, 2` is how many pixels `x` and `y` change on every pass through the loop — the `d` is short for "the difference this pass."

The `while running:` loop is the heart of every pygame program. Like the `loop()` function from Project 00 of Unit 01, this runs over and over, as fast as `clock.tick(60)` allows, for as long as `running` stays `True`.

`for event in pygame.event.get():` checks everything that happened since the last time through the loop — a key press, a mouse click, or the window's close button. Your program never sends `pygame.QUIT` itself — macOS sends it the moment you click that close button, and it shows up in the list `event.get()` hands back. `if event.type == pygame.QUIT:` catches that one specifically and sets `running` to `False`, which ends the loop. In other words: clicking the window's close button — the red circle in the top-left corner — is what ends the program. Without this line, that click would do nothing, and macOS would think your program had frozen.

`x += dx` and `y += dy` move the square a little on every pass. Since this happens 60 times a second, it looks like smooth motion instead of a square jumping from spot to spot.

The two `if` lines are the bounce. `x + size` is the square's right edge — when that edge reaches `400`, the window's right edge, or when `x` itself reaches `0`, the window's left edge, `dx = -dx` flips the sign of `dx`, so the square starts moving the opposite direction. The `y` check does the same thing against the top and bottom of the window.

`screen.fill((0, 0, 0))` paints the whole window black before drawing anything new. Skip this and the square would smear a trail behind it instead of appearing to move.

`pygame.draw.rect(screen, (255, 255, 255), (x, y, size, size))` draws the square: on `screen`, in the color `(255, 255, 255)`, at the square's current position and size. Colors in pygame are three numbers for how much red, green, and blue light to mix — `(0, 0, 0)` is black, `(255, 255, 255)` is white.

`pygame.display.flip()` actually shows what you just drew. Pygame draws behind the scenes first so nothing flickers, and `flip()` is what puts it on screen.

`pygame.quit()` shuts pygame down cleanly once the loop ends.

## Step 4: Tell uv this program needs pygame

`square.py` needs a package that plain Python does not come with. Tell uv:

```
uv add --script square.py pygame
```

This writes a short note at the top of `square.py` that tells uv exactly which package this file needs. From now on, `uv run square.py` installs pygame automatically the first time and reuses it after that — you never have to install it by hand.

## Step 5: Run it

```
uv run square.py
```

A black window should open with a white square bouncing around inside it. Click the window's close button, the red circle in the top-left corner, to end the program.
